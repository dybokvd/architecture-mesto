# Сдача проектной работы 1 спринта

## Задание 1

### Зоны ответственности микрофронтендов

Разделение на микрофронтенды произведено следующим образом:

- _host-microfrontend_ отвечает за маршрутизацию — отрисовку нужных микрофронтендов в зависимости от URL, отрисовку хэдера и футера, а также за хранение информации о пользователе и передаче ее в дочерние микрофронтенды. Являясь приложением-хостом, данный микрофронтенд ничего не экспортирует, а наоборот — его конфигурация содержит в себе информацию о том, откуда необходимо подгружать все остальные микрофронтенды;
- _auth-microfrontend_ отвечает за страницы логина и регистрации. Соответственно, модуль данного микрофронтенда экспортирует два компонента —
  `Login` и `Register`;
- _profile-microfrontend_ отвечает за отображение блока профиля на главной странице, а также за функционал изменения данных профиля и аватара.
  Модуль данного микрофронтенда экспортирует один компонент с названием `Main`;
- _places-microfrontend_ отвечает за отображение карточек мест, их добавление и удаление, а также за функционал проставления лайков. Данный модуль также экспортирует один компонент — `Main`.

### Обоснование используемой технологии

В качестве инструмента для создания микрофронтендов выбрана технология Module Federation в виду наличия опыта работы с ней, а также потому, что главный аргумент в пользу использования ее альтернативы – возможность использовать различные фреймворки для разных микрофронтендов – кажется в рамках этого проекта менее весомым.

### Локальный запуск

Для локального запуска в проекте каждого микрофронтенда был настроен dev-сервер webpack, по умолчанию запускающийся на своем собственном уникальном порту. Чтобы запустить проект, необходимо в фолдере каждого микрофронтенда выполнить последовательно две команды: `npm ci` и `npm run start`. Приложение-хост запустится на 3000 порту, поэтому результат запуска можно увидеть в браузере по адресу `http://localhost:3000/`.
